## 4. Catatan Minor — Status Resolusi

Semua catatan yang bisa diselesaikan lewat kode **sudah diperbaiki** di sesi
ini (commit lanjutan). Sisanya butuh tindakan infra/perangkat.

1. ✅ **Kode referal "Belum tersedia"** (P11) — kini di-*derive* deterministik
   dari uid (`UserModel.kodeReferalDari`) saat field kosong, jadi setiap akun
   (termasuk seeded lama) selalu punya kode stabil yang bisa disalin.
2. ✅ **Banner "Diproses" menutupi konten** — Beranda kini menambah ruang
   gulir bawah (108→176 px) saat ada order aktif, sehingga kartu Pesan Ulang
   tidak lagi tertutup banner mengambang.
3. ✅ **Foto kru kosong di A5** (CORS web) — avatar pakai `foregroundImage`
   dengan child inisial permanen: bila gambar gagal dimuat, inisial tetap
   tampil (bukan lingkaran kosong). Untuk benar-benar memuat foto di web,
   config CORS disiapkan di [`firebase/cors.json`](../../firebase/cors.json)
   + panduan [`firebase/CORS-README.md`](../../firebase/CORS-README.md)
   (butuh `gsutil`, dijalankan sekali oleh Anda).
4. ✅ **QRIS belum diunggah** — placeholder informatif sudah ada (fix #3).
   Tindakan Anda: unggah QRIS asli via A6 → Rekening & QRIS → Edit.
5. ✅ **Kuota voucher** — terbukti naik (POTONG10K 1/150) setelah bug #4
   diperbaiki; increment atomik berfungsi.
6. ⏳ **Suara notifikasi mp3** — channel v2 + aset terpasang; **butuh HP fisik**
   untuk memastikan bunyi (speaker emulator tidak andal). Belum bisa
   diverifikasi dari sesi ini.

## 5. Uji Order #2 — Checkout Voucher + Tunai (bukti bug #4)

Alur lengkap dijalankan ulang dari nol setelah fix QRIS terpasang:

1. P4 → P5: paket Reguler 2 jam, tanggal **Rabu 15 Juli 2026**, slot 15.00,
   alamat "Terakhir Dipakai" (titik tervalidasi dalam area Sampit).
2. P6: voucher **POTONG10K** diterapkan — subtotal 90.000 → total **80.000**
   ([pel-06b](sweep/pel-06b-voucher-order2.png)).
3. P7: QRIS dipilih → **placeholder fix #3 tampil benar**
   ([pel-07d](sweep/pel-07d-qris-fix.png)); pindah ke **Tunai**
   ([pel-07e](sweep/pel-07e-tunai.png)) → Konfirmasi Pembayaran →
   **GAGAL** "[cloud_firestore/unknown] null"
   ([pel-07f](sweep/pel-07f-konfirmasi.png)) → bug #4 ditemukan.
4. Rules diperbaiki & dideploy → alur diulang penuh → **SUKSES**:
   - Order dibuat, banner beralih ke "Menunggu Penugasan"
     ([pel-07g](sweep/pel-07g-tunai-sukses.png)) — alur tunai memang
     melewati verifikasi bayar dan langsung antre penugasan.
   - Counter voucher **POTONG10K naik ke kuota 1/150** di A7
     ([adm-07b](sweep/adm-07b-voucher-terpakai.png)) — increment atomik +
     klaim per-nomor tercatat.
   - Order muncul di A3 sebagai **Rp 80.000 · Aktif · "Tugaskan kru"**
     ([adm-03b](sweep/adm-03b-pesanan-voucher.png)) — harga diskon tersimpan
     benar dan siap ditugaskan admin.

Dua lapisan akar masalah bug #4 di `firestore.rules`:
- `orders.create` menuntut `totalHarga == hargaSatuan × kuantitas` — mustahil
  terpenuhi saat ada potongan voucher ataupun add-on.
- `voucherUsages.read` menyentuh `resource.data.userId` — error saat
  transaction membaca dokumen klaim yang belum ada (cek sekali-per-nomor) →
  seluruh transaksi ditolak. Kini `get` cukup signed-in, `list` tetap ketat.

## 6b. Notifikasi chat kru ↔ pelanggan (sesi lanjutan)

Prioritas utama — **berfungsi dua arah, terverifikasi live**.

- **Akar masalah**: aplikasi pelanggan belum punya setup FCM sama sekali (tak
  ada token/handler); hanya kru. Chat tak pernah memicu notifikasi apa pun.
- **Perbaikan**:
  - Pelanggan kini mendaftarkan token FCM (`users/{uid}.fcmTokens`) + minta
    izin notifikasi + background handler + channel (tanpa FGS).
  - Cloud Function **`onChatMessageCreate`** (deployed) menentukan penerima
    dari `senderId` (pelanggan→semua kru tertugas, kru→pelanggan), menulis
    notifikasi in-app, dan push FCM (bersihkan token invalid).
- **Bukti live**:
  - Kru kirim → pelanggan terima "Pesan dari Demo Kru"
    ([notif-01](sweep/notif-01-kru-to-pelanggan.png)).
  - Pelanggan kirim → kru terima "Pesan dari Demo Pelanggan"
    ([notif-02](sweep/notif-02-pelanggan-to-kru.png)).
  - Bonus: "Tugas baru untuk Anda" (push penugasan) juga sampai ke kru.

Catatan CORS: hanya memengaruhi Admin Web (native pelanggan/kru tak
terpengaruh) dan butuh `gsutil` sekali — belum bisa diterapkan dari sesi ini
(tooling tak tersedia). Fallback inisial sudah membuat UI admin rapi.

## 6c. Hardening produksi — SEMUA SELESAI

Seluruh item hardening dari §7 sudah dikerjakan sesi ini:

1. **Anti double-tap** — P7 (Konfirmasi) & P10 (Kirim Ulasan): loading di-set
   sinkron sebelum await + guard.
2. **Validasi uang backend** — `onOrderCreate` hitung ulang potongan dari
   dokumen voucher (`potonganFormulaVoucher`); klien tak bisa klaim potongan >
   formula voucher, tanpa voucher potongan dipaksa 0; total/subtotal/potongan
   dikoreksi server. **Deployed.**
3. **Privasi order (`orders.get`)** — kunci slot dipindah ke koleksi `slots`
   publik-boolean (tanpa PII: hanya serviceId/jadwal/orderId/userId/taken);
   `watchSlotTerisi` + atomic-lock baca dari `slots`; `orders.get/list`
   dibatasi ke peserta+admin → cegah enumerasi detail pesanan lewat ID slot
   deterministik. Order lama di-backfill (function sekali-jalan, lalu dihapus).
   **Rules deployed & diverifikasi** ([slot terkunci](sweep/hard-01-slot-locked.png),
   [order baru sukses](sweep/hard-02-neworder-ok.png)).
4. **Migrasi field seeded** — `users.kodeReferal` (7 diisi), kru rating,
   voucher `terpakai` (function sekali-jalan).
5. **Animasi & polish** — `pageTransitionsTheme` FadeForwards (transisi rute
   halus konsisten) + skeleton loader P8 tracking. (TkButton press-scale & P9
   skeleton sudah ada sebelumnya.)

**Rekomendasi hardening sebelum go-live (belum dikerjakan, urut dampak):**
1. **Validasi nominal potongan di backend.** Rules kini memastikan
   `total == subtotal − potongan` dan voucher-nya `exists`, tapi *besar*
   potongan divalidasi ulang di transaction klien. Idealnya finalisasi
   pembayaran & potongan lewat Cloud Function (admin SDK) agar klien tidak
   pernah menentukan angka uang — sesuai prinsip skema TA.
2. **Batasi pembacaan `orders.get` yang kini terbuka untuk semua signed-in**
   (dipakai cek slot). Pertimbangkan koleksi `slots` terpisah yang hanya
   memuat status penuh/kosong, agar detail order tak terekspos lintas-user.
3. **Idempotensi order.** `slotOrderId` mengunci 1 slot/jadwal (bagus), tapi
   tambahkan guard UI anti double-tap "Konfirmasi" (disable tombol saat
   `loading`) untuk cegah dua percobaan beruntun.
4. **Konsistensi field dokumen seeded.** Beberapa dokumen lama kurang field
   (`kodeReferal`, `rataRating`, `jumlahUlasan`, `terpakai`). Sudah ditambal
   dengan `get(...,0)`/derive di kode, tapi sebaiknya jalankan skrip migrasi
   sekali untuk mengisi field agar rules & query tetap sederhana.
5. **Foto CORS jangka panjang.** Setelah CORS diset, pertimbangkan CDN/resize
   thumbnail agar panel admin tidak menarik gambar penuh.
6. **Animasi & polish** (backlog "kurang animatif"): tambah transisi halus
   antar-tab dan micro-interaction pada tombol utama; skeleton loader sudah
   ada di Beranda/K2, bisa diperluas ke P8/P9.
